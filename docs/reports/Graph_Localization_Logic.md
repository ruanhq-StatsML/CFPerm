# 图上 localization：逻辑，以及还能按哪些粒做

Prototype。不是 GNN，不是因果图，不是归因。

图 localization 和塔对照、特征族对照是 **同一条协议**，只是切 X 的刀换成了图。  
FSDS 仍是后面那一刀：有 Y，而且只打在 localization 标成 moved 的粒上。其他都还好说。

---

## 0. 一句逻辑

**图不是判决，是坐标。**

把左窗行为建成图，再按图上的粒把 X 切开。每一粒单独问、没有 Y：

> 光看这块画像，early vs late 还像不像同一堆东西？

读法只有 **动了 / 没动**。  
定位的是 **哪一块图画像换了**，不是哪一个点导致了转化。

和审核侧「视频塔动了、文本塔没动」同一句话，只是粒换成：用户连通、货连通、店结构、1-hop 池化的视频/音频、社区 mix、clk 图 vs cnv 图……

AUC、MMD、last-two 都是这块有没有分开的 **日志**。objective 仍是 moved / quiet。

---

## 1. 三层不要混

| 层 | 问的问题 | Y | 图在干什么 |
|---|---|---|---|
| 建图 | 谁和谁有边 | 不要 | 左窗 clk/cnv 连边；曝光不成边 |
| **localization** | 哪一粒画像动了 | **不要** | 刀：按实体 / 关系 / 半径 / 塔 / 社区切开 |
| FSDS | 动了的那粒和 Y 缺口有没有关系 | 要 | 只 drill moved；Δ 仍不是 treatment |

Localization 出名单。FSDS 拿名单。  
用 Y 去决定「哪块图重要」，就不是 localization 了。

这次 prototype 已经把两刀拆开：`user_connectivity` 动了，L1 LOGO 在 `graph_user` 上 ≤0。画像动 ≠ Y 缺口来源。

---

## 2. 现在这套 prototype 钉死的 procedure

### 2.1 一张冻住的左窗图

四张关系，都只来自每人时间中位切开后的 **左窗**：

| 图 | 边 | 现在抽的标量 |
|---|---|---|
| user—item | clk/cnv，去重 | `g_u_item_deg`, `g_i_user_deg` |
| user—merchant | 同上，经 item 挂店 | `g_u_merch_deg`, `g_m_user_deg` |
| session co-click | 同场 ≥2 个点击的 item—item | `g_i_coclick_deg` |
| shop projection | 共客投影 | `g_m_pr`, `g_m_clust`, `g_m_proj_deg` |

曝光不成边。clk 和 cnv 目前捆在一起成边。

行是 post-click 订单。时钟 W = `t_end` 中位。图特征 merge 回订单行。  
所以这一刀问的是：

> **后来的单 / 后来的人，在这张已经冻住的左窗图上，画像像不像早的人？**

不是「图的拓扑自己有没有随时间长出另一张图」。那是另一刀，见 §4.H。

### 2.2 按实体类型切粒（已跑）

| 粒 | 列 | 这次 AUC | moved |
|---|---|---:|---|
| user_connectivity | 人连了多少货、多少店 | 0.605 | yes |
| item_connectivity | 货被多少人点、同场共点 | 0.523 | no |
| merchant_structure | **当前这一单的店** 的度数 / PR / 聚类 | 0.501 | no |
| video_tower | 人走过的店，64 维视频 DGP 均值 | 0.829 | yes |
| audio_tower | 同上，音频 | 0.853 | yes |

视频/音频不是生产塔。catalog 1e4 个 id，商户上乱七八糟 attach，再聚到用户。协议和真塔一样：挂在图的节点上，沿边聚合，再当一粒打 W。

### 2.3 检测器

每粒：只有 `X_grain`，拟合 P(W | X_grain)，hold-out AUC ≥ 0.55 → moved。  
没有 Y。阈值是日志门，不是成绩。

## 3. 这次结果把逻辑说清楚的地方

`merchant_structure` 没动，`video_tower` / `audio_tower` 动得很响。不是矛盾。

- `g_m_*`：这一 **行** 挂的那一家店，店上 4 个图标量。
- `vid_*` / `aud_*`：这个 **人** 左窗走过的店，1-hop 池化后的 64 维。

同一张图，粒不同。  
店侧 4 个数还像；人侧「走过哪些店的味道」不像。零向量比例 early/late 只有 0.035 / 0.047，不是缺测。DGP 也没有灌 W/Y。

localization 要的就是这种并排：哪一粒动、哪一粒静。不要收成「所以是视频塔」。

## 4. 图 localization 还可以按哪些粒做

下面都还是 **无 Y、moved / not-moved**。能做，不必一次做完。FSDS 仍然只接 moved 的名单。

### A. 按实体类型 — 已做

人 / 货 / 店 三端各打各的。最粗的刀。  
读法：人端连通动了、货端没动 → 后来的人 **点多少** 不像，不是货的度数分布先漂。

### B. 按关系 / 哪张图 — 现在捆着，可拆

现在 `user_connectivity` 把 G_ui 和 G_um 捆在一粒里。可拆成四粒：

| 粒 | 只看 |
|---|---|
| rel_user_item | 人—货度数 |
| rel_user_merch | 人—店度数 |
| rel_coclick | 同场共点 |
| rel_shop_proj | 投影 PR / 聚类 / 投影度 |

读法：人—货边动了、人—店边没动。工单是「货侧召回/共点」还是「进店结构」，不是「图重要」。

### C. 按边类型 / act — 可做

现在 clk+cnv 一起成边，曝光明确不成边。下一刀可以把图拆成：

| 图 | 边 |
|---|---|
| G_clk | 只点击 |
| G_cnv | 只转化 |
| G_exp | 若要看曝光覆盖，单开；不要和点击图混成边 |

同一批人、同一时钟，三张图并排 localization。  
点击图动了、转化图没动：点的结构换了，成交结构还像。仍然不是「点击图害了 CVR」。

### D. 按 hop 半径（ego）— 最关键的下一刀

这是图 localization 真正比表模型多出来的几何。

| 半径 | 这块 X | 这次已经碰到的 |
|---|---|---|
| 0-hop | 节点自己：度数、是否枢纽 | `g_u_item_deg`, `g_u_merch_deg` |
| 1-hop | 邻居集合的汇总：邻居度数均值、走过的店的塔、邻居类别 mix | 视频/音频用户池化 |
| 2-hop | 店的其他客、共点 2 跳、投影上的邻居 | 还没做 |

同一实体、不同半径，必须分开打。  
0-hop 没动、1-hop 动了：不是「人少了」，是「人周围那圈货/店换了」。  
这次正好是：0-hop 人连通 0.605 动了；当前店 0-hop 结构 0.501 没动；1-hop 塔 0.83+ 动了。半径写进粒名，对照才硬。

### E. 按节点上挂的塔 — 已做 DGP，真塔同一协议

商户节点挂向量 → 沿 user—merchant 边聚到人 → 一粒。

真数据里同一句：

- 视频塔 / 音频塔 / 文本标题 / 类目 / 价带 embedding
- 先 attach 在 item 或 merchant，再决定在哪一跳聚合（人侧均值、当前店、当前货）

聚合点也是粒：人侧池化 vs 当前店向量，不要合成一块再事后分解。这次人侧 64 维动了、当前店 4 标量没动，就是这个差别。

### F. 按社区 / 切 — 可做

在 shop projection 或 user—item 上跑 Leiden / Louvain（无 Y）。

粒可以是：

- mix：这个人的触点落在哪些社区（占比向量）
- 社区内连通 vs 社区间连通
- 只对某个社区诱导子图再打一遍 A–D

读法：人坐的社区换了 / 没换。  
不要写成「社区 7 是根因」。社区标签是 X 的又一块，和类目 mix 同类。

### G. 按角色 / 分层 — 可做

两种切法，别混：

1. **特征粒**：枢纽性（度数、PR）单独一粒 vs 长尾一粒。
2. **行子集**：只在枢纽用户上做 localization，再只在长尾上做一遍。问的是 **动发生在图的哪一层**。

(2) 是「哪里动了」，仍无 Y。不要把枢纽用户的 AUC 当成「枢纽驱动转化」。

### H. 行对行 vs 图对图 — 两刀都合法，问题不同

| 刀 | 现在 | 另一刀 |
|---|---|---|
| 行对行 | 一张冻住左窗图，行按 t_end 切 W | 后来的人在这张图上像不像 |
| 图对图 | 还没做 | 左窗再切成 G_early / G_late 两张快照，比度数分布、assortativity、三角形、谱 |

图对图是 last-two 打在 **图摘要** 上，样本是窗不是订单。  
两刀可以并排：人换了（行对行动）、图还是同一张骨架（图对图 quiet），或反过来。不要合成一个「图谱漂了」。

### I. 二过：先粒、再点 — 可做

第一过：family / 半径 / 塔，出 moved 名单（现在这样）。  
第二过：只用 moved 那粒的 X，打 P(W | X_grain)，看哪些行「长得像后来」。

得到的是 **后来画像的坐标**（哪些人、哪些店看起来像晚窗），仍不是谁导致 Y。  
然后 FSDS 可以只在这些行上 drill，也可以仍在全表、只限 moved 列。两套都要写清楚样本。

### J. 谱 / 图 embedding — 可做，协议同塔

左窗图的 Laplacian 前 k 维、或 node2vec，当作又一座「图塔」，按实体挂上，再按 D/E 聚合。  
localization 问谱坐标动没动。不要叫 GNN 归因，也不要用 Y 去训这个 embedding 再回头说定位到了图。

### K. 路径两端 — 和 hop 板是同一把尺子

user → item → merchant 这条路径，localization 按 **端** 切（就是 A），FSDS 按 **跳** 切（L1 hops）。  
不要第三种「路径贡献度」。两端谁动谁静，已经是路径上的 localization。

## 5. 建议的对照表（同一时钟只填动 / 不动）

| 粒 | 半径 / 关系 | 动了？ | 不读成 |
|---|---|---|---|
| 人 0-hop 连通 | G_ui ∪ G_um 度数 | 这次 yes | 「用户图导致转化」 |
| 货 0-hop 连通 | 度数 + 共点 | 这次 no | 「货图没问题所以不用看」 |
| 当前店 0-hop 结构 | 投影 4 标量 | 这次 no | 「店没变」——只是这一单的店标量没把 W 分开 |
| 人 1-hop 视频池化 | 沿进店边 | 这次 yes | 「视频塔是根因」 |
| 人 1-hop 音频池化 | 沿进店边 | 这次 yes | 同上 |
| clk 图 vs cnv 图 | 边类型 | 还没打 | |
| 社区 mix | 投影切 | 还没打 | |
| 图对图快照 | 窗级摘要 | 还没打 | |

映射 fire 另列，要有 Y，走 FSDS / last-two。localization 表 **不填** 映射列。

---

## 6. 和 FSDS 怎么接（已经在做）

```
建图（无 Y）
  → 按粒 localization（无 Y，moved / quiet）
    → 只把 moved 的 hop/family/列 交给 FSDS（有 Y）
```

漏斗 hop 留在 L1 板上，是为了 **并排比较**，不是让漏斗来「解释图」。  
LOGO Δ≤0：这粒不是这个时钟上的 Y 缺口来源。RF-mass 仍可说明 P(X) 这块很响。两句话都要留着。

---

## 7. 不要做的

| 做 | 不做 |
|---|---|
| 按图的粒切开 X，无 Y 打 W | 用 GNN saliency / 梯度 当 localization |
| PageRank、聚类当 **画像坐标** | PageRank 当「对 Y 的重要性」 |
| 社区 membership 当 mix 粒 | 「社区 7 贡献了 40% 转化」 |
| 1-hop 塔和 0-hop 度数并排 | 合成一块再事后分解 |
| 二过标出「长得像后来」的点 | 把这些点写成 treatment / 根因 |
| 图对图、行对行分开写 | 一句「图谱漂了」 |

---

## 8. Prototype 若再加一刀，先加哪几粒

不必一次铺开。和这次协议兼容、也最能把逻辑说硬的是：

1. **拆关系**：G_ui / G_um / G_co / G_m 各打一粒（B）
2. **写明半径**：0-hop / 1-hop / 2-hop 当 family 名（D）
3. **拆边**：G_clk vs G_cnv（C）
4. **社区 mix** 挂在投影上（F）
5. 需要看「图骨架自己有没有换」时，再加 **图对图** last-two（H）

前三刀仍然是行对行、左窗冻图、无 Y。第四刀还是 mix。第五刀换样本单位（窗），表头要另写。
