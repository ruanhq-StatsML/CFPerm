# 商户 · 作者 · 商品 · 订单：图上两级实时归因

> **要什么**：实时（或近实时）先告诉你 **哪 2–3 个维度出了问题**，再在这些维度里做下一层归因。  
> **不要什么**：全空间唯一因果根因；也不是去做推荐/带货产品。  
> **方法句式**：图 localization（缩维）→ FSDS / LOGO（维内定位）→ 动作只砸子集。

---

## 1. 四个刻画维度（先并到一张图）

把业务对象收成 **同一张归因图** 上的节点类型（定位维度），边只表示关联（ASSOC / HSIC 等），不宣称因果：

| 维度（节点层） | 刻画什么 | 典型信号（示意） |
|----------------|----------|------------------|
| **商户 (Merchant)** | 店 / 卖家侧供给与履约画像 | 店龄、履约率、退款率、在架结构 |
| **作者 (Author/Creator)** | 内容 / 达人侧带货与表达 | 场次、粉丝结构、话术/素材风格、带货转化 |
| **商品 (Product/SKU)** | 货盘与同品漏斗 | 价带、类目、同品 clk→cnv、曝光结构 |
| **订单 (Order)** | 成交粒 / 转化粒路径 | 当场、时延、空路径、买后行为、金额 |

可选挂载（仍是同一图，别另起炉灶）：**用户 / 场次 (User·Session)** —— 和仓库三塔里的 User / Ctx 同构。

```text
        商户 ── 作者 ── 商品 ── 订单
          \       |       |       /
           └──── 用户/场次 ──────┘
```

边 =「这两层 KPI / 表征在共变」；告警对象 = **子图或 2–3 个高亮维度**，不是单点乱 explainer。

## 2. 能不能实时？——能（近实时窗）

| 层级 | 时钟 | 输出 | 延迟量级 |
|------|------|------|----------|
| **L0 检测** | 流式 batch / 日切 / 小时窗 | 有没有制度/质量 hop（OnlineRFPerm 等） | 窗长（分钟–小时） |
| **L1 图 localization** | 同一窗上滚 ASSOC 边 + 层 mass | **哪 2–3 维**在告警子图里 | 与窗同步 |
| **L2 维内归因** | 只对告警维跑 FSDS / LOGO / 组内 LOCO | 维内哪族特征、哪类实体切片 | 窗内或窗+1 |
| **L3 动作** | 只刷新/限流/抽审该维 | 工单落到商户运营 / 作者运营 / 货盘 / 交易 | 实时处置 |

**实时归因** = L0→L1→L2 挂在滚动窗上，不是离线月报才算一次。  
全量四维每次都跑细归因 = 贵且噪；**先 L1 缩到 2–3 维再 L2** 才是可上线形态。

## 3. 两级逻辑（你要的顺序）

### 3.1 第一级：图上 localization →「哪两三个维度有问题」

对当前窗 \(W_t\) vs 参考窗 \(W_{t-1}\)（或 quiet 基线）：

```text
① 每维聚一层「层指标 / 层表征」
   商户层、作者层、商品层、订单层（+用户/场次）

② 建/更新图 G_t
   节点 = 维；边 = 跨维指标 HSIC/ASSOC 超阈
   （例：作者带货转化 ↔ 订单空路径 ↔ 商品曝光结构 连成链）

③ 图 localization
   - 连通告警分量 / 高权边链
   - 或 leave-one-dimension-out：拿掉哪一维后窗间距离掉最多
   - 输出：Top-2/Top-3 维度集合 S* = {商户?, 作者?, 商品?, 订单?}

④ 对外第一句话（给值班）
   「本窗问题维：作者 + 订单（商品边缘）；商户安静」
```

这一层 **只回答维度**，不回答「哪个 SKU、哪个达人」——那是第二级。

### 3.2 第二级：在 S* 上做下一层归因（FSDS）

只对 \(S^*\) 里的维度：

```text
⑤ 维内特征家族 / 实体切片
   例：S*={作者, 订单}
   - 作者维：话术/风格族、场次族、粉丝结构族 …
   - 订单维：路径时延族、空路径、当场、买后点击 …

⑥ FSDS 两轴（纪律不变）
   RF-domain → 这维上「后来的对象长什么样」P(X)
   PO-risk   → 这维上谁和 Y 差绑在一起（概念相关，非因果故事）

⑦ 组内再钻（可选）
   LOGO 家族 → 组内 LOCO/CFPerm 到单特征或 Top 实体桶

⑧ 动作路由（只砸 S*）
   作者维 mass 高 → 作者侧素材/达人运营/限流该作者桶
   订单维 mass 高 → 交易路径/空路径监控/转化粒策略
   商品维安静 → 不开货盘大动作
```

### 3.3 一张图

```text
滚动窗到达
   │
   ▼
检测：漂了/火了吗？ ──quiet──► 不归因、不扰民
   │ fire
   ▼
【L1 图 localization】
  商户·作者·商品·订单(+用户) 并维建图
   → 输出 S* = 2～3 个问题维
   │
   ▼
【L2 FSDS 维内归因】
  仅在 S* 上 RF/PO mass + 组内钻取
   → 输出：族 / 切片 / Top 实体桶
   │
   ▼
处置：只给 S* 对应 owner 开工单
```

## 4. 和仓库已有形状怎么对齐（不是新故事）

| 这里的维 | 仓库里同构的块 | 已有读法 |
|----------|----------------|----------|
| 订单维 | 转化粒 / Ctx·路径 / attr asof | 路径是刻画；FSDS 说它是不是漂移源 |
| 商品维 | SKU 塔（有构成率闸） | 稀缺时闸关，不硬归因 |
| 用户/场次 | User 塔 · session 族 | 队列画像 vs 场内成交 |
| 商户/作者 | 层节点（user–item–session–**merchant** 报告已写） | 同一套分层子集定位 |

三塔 User/Ctx/SKU = **三维特殊情况**；商户·作者·商品·订单 = **四维（可扩）同一套两级 localization**。

## 5. 实时输出长什么样（值班可读）

```text
窗: 2026-09-16 10:00–11:00 | fire=1
L1 问题维: 作者 (0.41), 订单 (0.33) | 商品 0.12 | 商户 0.08
L1 告警链: 作者带货转化 — 订单空路径 — 当场深度
L2 作者: RF 高=粉丝/场次画像；PO 高=话术/素材族 → 开作者素材工单
L2 订单: PO 高=空路径/当场成交深度 → 开转化路径监控；attr 时延 LOGO≈0 → 别讲「决策变慢」
动作: 限流作者桶 A；抽审订单空路径 Top-k；商品/商户本窗不动
```

## 6. 纪律（避免讲砸）

| 要 | 不要 |
|----|------|
| L1 先出 2–3 维 | 一上来全维单特征 explainer |
| L2 只在 S* 内 FSDS | 把 ASSOC 边讲成因果 |
| asof/路径 = 刻画 | 路径时长直接当 CATE |
| 近实时滚动窗 | 等月报才「归因」 |
| 方法 use-case：定位+开工单 | 借机做推荐/带货中台 |

## 7. 一句

**能实时。** 先把商户·作者·商品·订单（+用户）收到一张图上做 **维度级 localization**，报出哪两三个维有问题；再只在这些维上做 **FSDS 下一层归因**——和多塔/三塔、特征家族是同一套两级子集定位，只是节点换成了业务实体维。

风格归因与图谱归因 **先并成特征维度** 再跑本流水线，见 `FEATURE_DIM_UNIFIED_ATTR.md` / `scripts/agod/feature_dim_attr.py`。

**刻画与评估（elaborate）**：`GRAPH_USECASE_EVAL.md` —— L1 Hit@K 为主考；L3 子集动作率；ASSOC 不进因果 KPI。
