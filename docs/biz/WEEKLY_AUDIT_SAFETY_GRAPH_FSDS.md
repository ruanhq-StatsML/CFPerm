# 周更审核 · 安全拒答 · 图谱定位→FSDS — 评估逻辑（concise）

> 方法 use-case，不是新模型。  
> 图谱落地句式：**先把对象并到一张图的一个定位维度 → 在该维度上做 FSDS 子集定位**。

---

## 1. 周更审核（RLHF / DPO 周合并）— 评估逻辑

### 1.1 对象

| 批 | 角色 |
|----|------|
| \(T=0\) | 上周已上线 / 黄金偏好批（参考） |
| \(T=1\) | 本周待合并偏好批（候选） |

\(X\) = prompt+回答表征（或现有 embedding）；\(Y\) = 偏好标签 / 裁判分。

### 1.2 评估步骤（每周一次）

```text
① 批式 RFPerm（或 Online 周窗）
   ref=T0 → 探针 μ0；在 T1 上算 OOS
   fire?  （相对 T0 / 相对上周 e_prev）

② quiet
   → 放行合并；人审配额 ≈ 0（或极少抽检）
   → 记录：本周「无制度 hop」

③ fire
   → 强制审核打开
   → po_risk0 对 T1 排序 → Top-k 人复核偏好对
   → 处置三档（评估选一）：
        拒合并 | 限量灰度合并 | Top-k 修完再合并

④ 轴拆分（合并前必跑，防混账）
   文风/画像轴高、偏好轴未火 → 素材/采样问题，不挡对齐合并
   偏好轴火、文风安静 → 真·映射 hop，走③
```

### 1.3 评估指标（对账用）

| 指标 | 通过标准（示意） | 含义 |
|------|------------------|------|
| `fired` | 周报必出 | 要不要进人审 |
| `ratio` / `judge_err_ratio` | 相对门禁 γ | hop 强度 |
| `n_audit = k` | 火了才 >0 | 人力是否按火情花 |
| `merge_decision` | pass / limit / reject | 发布结果 |
| 假放行代价 | 下周一线上偏好投诉/回滚 | 门禁价值（防损） |

**一句：** 周更审核 =「本周合并有没有换偏好制度」；quiet 放行，fire 才砸 Top-k。

## 2. 安全拒答 — 评估逻辑

### 2.1 对象

把 **安全动作** 当标签，不要只盯「模型好不好」：

| 符号 | 含义 |
|------|------|
| \(Y_{\text{safe}}\) | 拒答 / 降级 / 放行（策略头输出） |
| \(Y^\star\) | 金标：该拒 / 该放（抽检或规则集） |
| \(X\) | 请求表征、意图、风险特征 |

### 2.2 两类失败（必须分列）

| 失败 | 定义 | 业务痛 |
|------|------|--------|
| **漏拒** | \(Y^\star=\)该拒，但策略放行 | 安全事故 |
| **误拒** | \(Y^\star=\)该放，但策略拒答 | 体验/承接掉、投诉 |

### 2.3 评估步骤

```text
① 制度监测（OnlineRFPerm）
   Y = 安全动作（或「是否与金标一致」）
   fire?  → 策略工作点 hop 了（不是流量画像换了就叫模型坏）

② 画像轴（FSDS / domain）
   若只是请求 mix 变了、安全映射没变 → 调配额/路由，不回滚安全头

③ fire 后子集
   按意图桶 / 风险等级 / 渠道 做 localization
   → 只审「漏拒·误拒」集中的那一桶

④ 人审 / 双跑
   旧策略 ∥ 新策略；Top-k（PO）优先审争议单
   指标：漏拒率↓、误拒率↓、拒答率水平是否异常跳变

⑤ 处置
   限量切流 | 回滚策略头 | 只改某一意图规则
```

### 2.4 评估指标

| 指标 | 读法 |
|------|------|
| 拒答率 level + hop | 有没有工作点跳变 |
| 漏拒率 / 误拒率 | 安全 vs 体验拆开 |
| `fired` on \(Y_{\text{safe}}\) | 要不要开策略审核 |
| 子集（意图/渠道） | 改哪条规则，不改全家桶 |

**一句：** 安全拒答评估 =「策略头工作点漂了没 + 漏拒/误拒分列 + 子集上改规则」。

## 3. 图谱落地逻辑（先并维 → 再 FSDS）

你要的顺序：

```text
多对象 / 多塔 / 多专家 / 多指标
        ↓
① 整合到「一张图」上的同一个定位维度
   （节点=塔/路/家族/意图/实体；边=ASSOC·HSIC 等关联，只声明关联）
        ↓
② 在该维度上做图级 localization
   （连通分量 / 高关联链 / 哪一层子图在告警）
        ↓
③ 对锁定的子图 / 节点集合 跑 FSDS
   （P(X) vs P(Y|X) 份额；哪族特征、哪路表征 mass 最大）
        ↓
④ 只对 FSDS 指出的子集开刷新 / 审核 / 回滚
```

### 3.1 为什么先「并到一个维度」

| 不做 | 做 |
|------|-----|
| 每个 KPI、每塔各跑各的，对不上 | 先有一张**统一定位图**，告警是「链/子图」 |
| 直接对全特征 FSDS（噪声大） | 先缩到子图，再 FSDS（子集更干净） |
| 把关联当成因果 | ASSOC 边只导钻取；FSDS 再给可动作的族 |

### 3.2 维度怎么选（LLM / 多塔常用）

| 图维度（节点类型） | 边的含义（示意） | 随后 FSDS 看什么 |
|--------------------|------------------|------------------|
| **模态塔** | 塔间一致性 / 同步漂 | 哪塔特征 mass |
| **专家 / Router** | 共现错分、同意图掉点 | 哪路专家表征 |
| **意图桶** | 质量指标联动链 | 该意图下的 X 族 |
| **特征家族** | 家族共变 | 族内 top 特征 |
| **审核对象** | 同批 fire 样本关联 | 审哪些 X 切片 |

### 3.3 一张极简流水线

```text
检测火了
  → 建/取业务图 G（节点=定位维度上的块）
  → 图 localization：取出告警子图 S ⊂ G
  → 在 S 上 FSDS：π_j 最大的块 j*
  → 动作：只刷 / 只审 / 只回滚 j*
  → （可选）PO Top-k：j* 内再排人审实例
```

**一句：** 图谱负责「先缩到哪一块子图」；FSDS 负责「子图里谁在解释漂移」——两级 localization，不是两套产品。
