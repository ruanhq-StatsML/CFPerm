\begin{abstract}
This note is a blunt serving use-case, not a new LLM method.
We cast four public QA corpora into the same tidy stream form
\texttt{t\_idx / batch / question / answer / y}, freeze a shallow probe on a
reference window with $n_{\mathrm{ref}}\ge 100$, and run OnlineRFPerm as an
online regime clock on the trail.
Quiet batches keep knowledge/context in the prompt; hop batches drop context
and force invent-style decoding, inducing a quality-law change.
We report fire index and detection delay, and (optionally) compare to the
\texttt{onlinePermOOB} baseline bank under the manuscript
\texttt{first}$_k$ counting rule.
Numbers below are from the current CPU/mock scaffold and are meant as a
starting point for your edits---not a final claim set.
\end{abstract}

\section{What this is / is not}
\paragraph{Is.}
A production-shaped wiring:
live (or simulated) LLM answers $\to$ tidy dataframe $\to$ OnlineRFPerm fire
$\to$ action route (\texttt{model\_rollback} / \texttt{retrieval\_refresh} /
\texttt{audit\_topk}).
\paragraph{Is not.}
A fact checker, a causal root-cause engine, or an LLM training paper.
Fire only opens a contrast window and a gate.

\paragraph{Regime construction (shared).}
\begin{itemize}[leftmargin=1.2em]
\item \textbf{Quiet} (batch $<$ cut): system $=$ faithful; prompt includes knowledge.
\item \textbf{Hop} (batch $\ge$ cut): system $=$ invent; knowledge removed.
\item Label $y=1$ (bad) from low token-overlap faithfulness vs.\ knowledge
(plus light invent-style heuristics on the hop window).
\end{itemize}

\section{Protocol}
\paragraph{Clock.}
$n_{\mathrm{per}}=20$, $\mathrm{cut}=5$ $\Rightarrow$
$n_{\mathrm{ref}}=n_{\mathrm{per}}\times\mathrm{cut}=100$ (meets the
$n_{\mathrm{ref}}\ge 100$ requirement). Total $n_{\mathrm{batches}}=10$ so the
trail has length $100$ observations / $5$ batches.

\paragraph{OnlineRFPerm (batch).}
On consecutive batches $B_{t-1},B_t$:
\begin{align*}
\mu_0 &\leftarrow \mathrm{fit\_online\_probe}(X_{t-1},Y_{t-1}),\\
e_t &= \mathrm{err}(\mu_0; X_t,Y_t),\\
\mathrm{fire}_t &\iff e_{t-1}\ge e_{\mathrm{floor}}
  \;\wedge\; e_t/e_{t-1}\ge \gamma.
\end{align*}
Reported: first fire batch, detection delay $=\mathrm{fire}-\mathrm{cut}$,
and quiet/hop mean $y$.

\paragraph{Manuscript \texttt{first}$_k$ (for baseline tables).}
Let \texttt{det} be the boolean trail (batches \emph{after} cut only). Then
\begin{verbatim}
def first_k_consecutive(det, k):
    det = np.asarray(det, dtype=bool)
    for i in range(len(det) - k + 1):
        if det[i:i+k].all():
            return i   # trail batch index; 0 = first batch after cut
    return None
\end{verbatim}
So \texttt{first}$_2$ $=$ ``从第几个 trail batch 开始，头一回连续两个 fire''.

On HaluEval / SQuAD / TruthfulQA the hop is sharp: quiet $y$ near zero, hop $y$
near one, and OnlineRFPerm fires at cut (delay $0$).

($y\approx 1$), so there is no usable contrast---treat as a negative control /
featurization TODO (long contexts $\Rightarrow$ overlap labels need tightening),
not as a method failure.

\section{Action routing (product sentence)}
On fire:
\begin{itemize}[leftmargin=1.2em]
\item low \texttt{rag\_hit} $\to$ \texttt{retrieval\_refresh};
\item fire with adequate retrieval support $\to$
\texttt{model\_rollback} / canary + \texttt{audit\_topk} via \texttt{po\_risk0}.
\end{itemize}
Quiet $\to$ standard path, weights anneal to uniform.

\section{Draft conclusion (for you to sharpen)}
\begin{enumerate}[leftmargin=1.2em]
\item The use-case is intentionally blunt: dataframe streams + OnlineRFPerm clock.
\item With $n_{\mathrm{ref}}=100$, three of four datasets show delay-$0$ fires at
the injected hop; HotpotQA needs label/context handling before it is diagnostic.
\item Baselines should be scored with the same \texttt{first}$_k$ trail-batch
rule as the PointCloud note; delay alone is not enough.
\item Next edits: regenerate streams with a real CPU/transformers (or vLLM)
backend; fill baseline tables; tighten Hotpot faithfulness; optionally attach
acted-vs-ignored ¥ only if a ledger is back on.
\end{enumerate}
