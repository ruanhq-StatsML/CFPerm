# Subset localization · 多塔/三塔 · 大模型审核 — 具体落地谈

> **立场**：用统计方法找 **生产 use-case**，不是做推荐系统、不是做新 LLM 算法。  
> 多塔 / 三塔只是「哪一块漂了就只动哪一块」的 **子集定位形状**。

---

## 1. Post-hoc subset localization 还有哪些？

共同句式：

```text
先确认「漂了 / 火了」
  → 再定位到子集（谁、哪路、哪族、哪类题）
  → 只对子集开动作 / 刷新预算
  → 不做全空间唯一根因分解
```

| # | 子集切法 | 业务问题 | 动作（只动子集） |
|---|----------|----------|------------------|
| L1 | **模态塔 / 多路表征** | 视·音·文哪一路漂了？ | 只刷该路 KV / 重编码 / LoRA |
| L2 | **三塔形状（user/item/context 等）** | 哪一塔表征在漂？ | 只重算/重训该塔；**不是做推荐产品** |
| L3 | **专家 / Router 路由** | 哪类题 / 哪路专家质量掉了？ | 只刷新该专家或该检索器 |
| L4 | **特征家族** | 哪一族特征在解释漂移？ | 修该族管道 / knockout / 补数 |
| L5 | **任务块 / 意图桶** | 物流题漂了还是退款题漂了？ | 只动该意图的提示/工具/检索 |
| L6 | **人群 / 区域 / 品类** | 哪段流量先坏？ | 限流、灰度、定向补数据 |
| L7 | **时间窗 / 批次** | 哪一周、哪次合并引入的？ | 回滚该批、隔离该合并 |
| L8 | **实例 Top-k（审核队列）** | 哪些样本最该人审？ | 审计人力只砸 Top-k |
| L9 | **轴拆分（文风 vs 偏好 vs RAG）** | 是画像漂还是映射漂还是检索缺口？ | 开不同工单，禁止混账 |

**L1–L3 是同一逻辑的不同皮肤**；L8 是审核专属的实例子集。

## 2. 多塔 / 三塔逻辑（具体看）

### 2.1 一句

不是「我们要上三塔推荐」。  
是：**系统里本来就有多路并行表征时，漂移往往只发生在一路**——定位到那一路再刷新，省算力、少误伤。

### 2.2 形状对照（同一方法，不同外壳）

| 外壳 | 路 / 塔 | 漂了之后生产动作 |
|------|---------|------------------|
| **LLM 多模态** | 视觉塔 · 音频塔 · 文本塔 | 只失效/重编码漂的那一路 KV；静止 caption 可复用 |
| **多专家 / MoE·Router** | 专家1 · 专家2 · … · 检索器 | 只刷新掉点的专家或检索索引 |
| **「三塔」形状**（user / item / context 等） | 三路 embedding | 只重算漂的那一塔；**产品可以是搜索、广告、推荐、风控——方法不管产品名** |
| **客服工具链** | 检索路 · 生成路 · 工具调用路 | rag_hit 低 → 只刷检索；生成制度 hop → 只动生成 |

### 2.3 生产闭环（多塔专用）

```text
1. 制度/质量火了吗？（OnlineRFPerm / 批式 RFPerm）
2. FSDS / 多层份额：π_塔 或 π_路 —— 谁的 mass 最大？
3. Post-hoc 子集 = 「该塔/该路」
4. 动作：只给该子集刷新预算（KV / 重编码 / LoRA / 索引）
5. 别全塔重算；别把文风轴当成生成制度轴
```

### 2.4 和「做推荐」的边界

| 要 | 不要 |
|----|------|
| 用三塔/多塔当 **定位切片** | 借方法去搭一套推荐业务 |
| 输出：哪塔漂、刷多少预算 | 输出：下一件买什么 |
| 价值：MTTD/MTTA↓、算力↓、误回滚↓ | 价值：GMV/CTR 归因故事 |

## 3. 大模型审核：落地场景具体谈

「审核」在这里 = **人 / 轻量裁判把关**，不是事实核查大模型本身。  
方法只回答：**该不该审、审哪批、先审谁、审完怎么处置**。

### 3.1 审核场景地图

| 场景 | 何时触发 | 审什么 | 方法角色 | 处置 |
|------|----------|--------|----------|------|
| **A1 线上差会话止血** | 推理制度火（OnlineRFPerm） | 当前窗高风险回答 | PO-risk Top-k 排序 | 人工改写/拦截；记审计件成本 |
| **A2 对齐合并门禁** | 新偏好批 vs 黄金批 fire | 偏好对 / 标注质量 | RFPerm-as-Judge | 拒合并 / 限量 / Top-k 复核后放行 |
| **A3 合成数据验收** | 每批合成样本入库前 | 合成偏好/问答是否偏离真人制度 | RFPerm-as-Judge（小样本 30–40 即可） | 隔离训练集；不合格整批退 |
| **A4 裁判/打分器校准** | 换裁判模型或提示词 | 裁判分相对黄金集是否 hop | 批式/在线 RFPerm | 双跑、限量切流、回滚裁判 |
| **A5 安全/拒答策略审核** | 拒答率或安全头工作点异常 | 该拒没拒 / 误拒 | 把安全动作当 \(Y\) 监测 | 策略双跑；别把流量画像当模型坏了 |
| **A6 检索支持审核** | fire + Top-k `rag_hit` 低 | 「答得差」是不是知识没检索到 | RAG 轴与生成轴拆开 | 审检索命中与文档，**不**先审生成文风 |
| **A7 Router 错分审核** | 某意图桶质量独崩 | 路由是否把题送错专家 | 按任务块子集定位 | 审路由规则 / 该专家；只修一路 |
| **A8 发布前抽检门禁** | canary / 灰度放量前 | 金标集上的制度是否相对基线漂 | 批式 RFPerm | 不通过则挡住全量 |
| **A9 周更连更复核** | RLHF/DPO 每周合并 | 合并引入的映射 hop | OnlineRFPerm + FDR | 火了才强制 Top-k 人审，quiet 放行 |

### 3.2 审核流水线（统一心智）

```text
参考批 / 上一窗  →  拟合轻量探针 μ0
当前批 / 当前窗  →  是否 fire？
    quiet → 不审或极少抽检（省人力）
    fire  → po_risk0 排序 → 人审 Top-k
         → 处置：拦截 / 改写 / 拒合并 / 只刷某一路
         → 成本：审计件¥ 进净贡献；动作日成本进回本
```

### 3.3 和客服账怎么接（审核有价）

| 项 | 含义 |
|----|------|
| `audit_topk` 动作臂 | 火情期开抽检队列 |
| 审计件 × 单价 | 从毛贡献扣成净贡献 |
| 回本 | 审计臂日成本低，往往 **当天回本** |
| 不审的代价 | 坏回答继续外溢 → 工单/退款升、承接掉 |

### 3.4 审核 **不是** 什么

| 不是 | 所以 |
|------|------|
| 事实核查器 | fire ≠「这句话事实错了」 |
| 道德裁判 | 不输出价值观对错 |
| 全量人审替代 | 只在 fire 后砸 Top-k |
| 和文风工单一回事 | 文风高 AUC → 素材账；审核走偏好/幻觉/安全轴 |

## 4. 三者怎么叠在一起（一张图）

```text
火了？（检测）
  ├─ 多塔/三塔/专家 子集定位 → 只刷漂的那一路     ← localization
  ├─ 检索 vs 生成 轴拆分     → 刷索引或回滚生成
  └─ 审核子集（实例 Top-k）  → 人审最该看的样本   ← 大模型审核
        ↓
  处置进经营账：少工单/退款/多承接 − 审计成本 − 动作日成本
```

**生产价值一句话**：检测告诉你「要不要动」；subset localization 告诉你「动哪一块」；审核告诉你「人眼先看哪几条」——三者都是方法的 use-case，不是新模型。
