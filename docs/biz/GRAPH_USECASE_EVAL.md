# 图谱 Use-case：怎么刻画 · 怎么评估（elaborate）

> **一句话**：图谱 use-case 不是「再做一个图神经网络产品」，而是  
> **把多对象业务先收成一张定位图 → 先报哪 2–3 个维有问题 → 再只在这些维里做特征/实体归因 → 只对子集开工单**。  
> 下面把 **刻画** 与 **评估** 拆开写死——这是对外 justify 的核心。

相关：`MERCHANT_AUTHOR_PRODUCT_ORDER_GRAPH_ATTR.md` · `FEATURE_DIM_UNIFIED_ATTR.md` · `WEEKLY_AUDIT_SAFETY_GRAPH_FSDS.md`  
可跑同构板：`scripts/agod/feature_dim_attr.py --alias graph`

---

## 0. Use-case 身份卡（先钉死「是什么」）

| 项 | 内容 |
|----|------|
| **业务问题** | 质量/转化/供给一窗里变差了——**先动哪一类对象**（商户？作者？商品？订单？）？ |
| **方法角色** | **子集定位的外壳**：节点=业务维，边=ASSOC（只声明共变） |
| **输出** | L1：`S* = Top-2/3 维`；L2：维内特征族 / 实体桶；L3：owner 工单 |
| **不是** | 推荐/带货中台；全空间唯一因果；把 ASSOC 边讲成 CATE |
| **和 LLM 同构** | 商户↔检索供给，作者↔文风/达人，商品↔内容单元，订单↔路径/工具链 |

**Justify**：值班不能同时开四条大动作。图谱的价值是 **缩决策空间**——先维后特征，和多塔「只刷漂的那一路」是同一句式。

## 1. 怎么刻画（Characterization）

刻画 = 规定：**节点是什么、边是什么、窗怎么切、每一层回答什么问题**。答不清这四件事，评估表会假。

### 1.1 节点：业务维（定位维度），不是单实体 ID

| 维 | 刻画对象 | 层表征 / 层 KPI（示意，可换你们字段） | Owner |
|----|----------|----------------------------------------|-------|
| **商户** | 店/卖家供给与履约 | 履约率、退款率、在架结构、店龄桶 | 商户运营 |
| **作者** | 达人/内容表达 | 场次、粉丝结构、话术/素材风格、带货转化 | 作者/内容运营 |
| **商品** | SKU/货盘 | 价带、类目、同品 clk→cnv、曝光结构 | 货盘 |
| **订单** | 成交/转化路径 | 当场、空路径、路径时延、买后行为、金额 | 交易/转化 |
| （可选）用户·场次 | 流量画像 | session 深度、来源、队列结构 | 增长/策略 |

**刻画纪律**

- L1 的节点是 **维**（类型），不是「某个具体达人 ID」——实体钻取放 L2。  
- 每维必须有 **可聚合的层向量 / 层 KPI**，否则建不了图、也评不了「维对不对」。  
- 文风指标挂在 **作者维**（或作者下的 register 子维），不要另起一套旁路产品。

### 1.2 边：ASSOC / HSIC 共变，只导钻取

```text
边 e(u,v) = 窗内「维 u 的层指标」与「维 v 的层指标」关联超阈
         ≠ 「u 导致 v」
```

| 边的合法读法 | 非法读法 |
|--------------|----------|
| 作者转化 ↔ 订单空路径 同窗共变 → 告警链上两维一起看 | 「作者导致空路径」 |
| 商品曝光 ↔ 订单当场 连成链 → L1 可能同时点亮 | 边权 = 因果效应 |

### 1.3 时间刻画：滚动窗（近实时）

| 符号 | 含义 |
|------|------|
| \(W_t\) | 当前窗（小时/日/batch） |
| \(W_{\mathrm{ref}}\) | 参考窗（上一窗 / quiet 基线 / 同比） |
| fire | L0：OnlineRFPerm 等制度/质量 hop（可没有则「软火」= KPI 超阈） |

**实时** = 每窗跑 L0→L1→（火了才）L2，不是等月报。

### 1.4 三层输出（刻画「答什么」）

| 层 | 问题 | 输出形状 | 不回答 |
|----|------|----------|--------|
| **L0 检测** | 这窗要不要归因？ | `fired ∈ {0,1}` + 对照窗 | 谁的错 |
| **L1 图 localization** | **哪 2–3 个维**有问题？ | `S*`, 维 mass, 告警链 | 哪个 SKU/达人 |
| **L2 维内归因** | S* 里 **哪族特征 / 哪类实体桶**？ | RF-mass / PO-mass / LOGO / Top 桶 | 全图唯一根因 |
| **L3 动作** | 开哪张工单、给谁？ | owner × 动作类型 | 推荐排序/出价 |

### 1.5 一张刻画总图

```text
对象流（商户·作者·商品·订单·用户）
        │ 按维聚合层 KPI / 层表征
        ▼
   图 G_t：节点=维，边=ASSOC
        │
   L0 火了？──否──► 安静，不扰民
        │是
        ▼
   L1：localization → S* = {作者, 订单, …}     ← 对外第一句
        │
        ▼
   L2：仅 S* 上 FSDS/LOGO → 族 / 实体桶         ← 对外第二句
        │
        ▼
   L3：只砸 S* 的 owner 工单                     ← 可对账动作
```

### 1.6 LLM 侧怎么刻画（同构，换皮不换骨）

| 业务图维 | LLM / 智能体同构维 | 刻画信号 |
|----------|-------------------|----------|
| 商户 | `rag_retrieval` | rag_hit、知识覆盖、索引批次 |
| 作者 | `style_register` | formal/hedge/length（**另账**） |
| 商品 | `text_payload` | 回答内容 hash / embedding |
| 订单 | `agent_path` | step_depth、tool_call、retry、route_entropy |

评估协议与业务图 **同一套**（见 §2），只换维名与层特征。

## 2. 怎么评估（Evaluation）

评估 = 规定：**每一层什么叫对、用什么指标、用什么实验设计**。  
禁止用「图好看 / AUROC 高」代替 use-case 成败。

### 2.1 评估总原则

| 原则 | 含义 |
|------|------|
| **分层评** | L0 / L1 / L2 / L3 分开报，不混成一个总分 |
| **有真值才硬评** | L1 维级用 **注入 hop / 已知坏维**；线上无真值时改用稳定性与动作对齐 |
| **ASSOC 不进因果 KPI** | 边质量用「是否帮助缩到真坏维」间接评，不评「边=因果」 |
| **动作可对账** | L3 最终看「只动 S*」是否减少误动作 / 节省刷新预算 |
| **另账不混** | 作者·文风维的 CTR/品牌 KPI **不进** 客服工单账 |

### 2.2 L0 检测怎么评

| 指标 | 定义 | 及格读法 |
|------|------|----------|
| Detection delay | 注入 hop 后第几窗 fire | 越小越好；报 delay=0/1/2 |
| Quiet 误火率 | 无 hop 窗 fire 比例 | 需可控（门控 / FDR） |
| 对照窗可用性 | fire 后能否划出 acted vs ignored | 有火才有后续归因意义 |

**无 L0 时**：可用「层 KPI 超阈」作软火，但评估表要单列，避免和方法 fire 混账。

### 2.3 L1 图 localization 怎么评（**图谱 use-case 的主考题**）

L1 答的是「维对不对」，这是图谱相对「直接全特征 FSDS」的 **差异化价值**。

#### （A）有注入真值时（实验室 / 演练，硬指标）

设计：在参考窗后，**只污染 1～2 个维**的层特征或层 KPI（其余维安静）。

| 指标 | 定义 | 目标 |
|------|------|------|
| **Hit@K** | 真坏维是否落在报出的 Top-K（K=2 或 3） | Hit@2 ≥ 约定阈值（如 0.8+） |
| **Precision@K** | Top-K 里真坏维占比 | 降误报维 |
| **Rank of true dim** | 真坏维的平均名次 | 越靠前越好 |
| **False dim rate** | 安静维被点亮的比例 | 越低越好 |
| **vs 全特征基线** | 不建图、直接全特征 Top 族，再映射回维 | 证明 L1 缩维 **不差于 / 优于** 扁平 FSDS 的维级召回，且噪声更低 |

```text
注入：只改「作者」层话术/风格族
期望：S* 含作者；商户·商品尽量不进 Top-2
失败：S*={商品, 商户} 而作者靠后 → L1 刻画或边权坏了
```

#### （B）线上无维级真值时（生产监测，软指标）

| 指标 | 定义 | 用途 |
|------|------|------|
| **维稳定度** | 相邻窗 S* Jaccard | 过高乱跳 → 窗太噪；过低一直同一维 → 可能粘滞 |
| **维-动作对齐率** | 报了作者维后是否开了作者工单（且未开无关维大动作） | 流程是否真按 L1 执行 |
| **误动作避免次数** | 本会全量刷新、因 S* 而只刷 1～2 维的次数 | 图谱的直接业务价值代理 |
| **告警链可读性** | 值班能否一句话复述 L1（人工抽检） | 刻画是否落地到人 |

### 2.4 L2 维内归因怎么评

只在 **真进入 S* 的维** 上评（别在全图上刷分）。

| 轴 | 指标 | 读法 |
|----|------|------|
| **RF-domain mass** | 维内各族对 \(W\)（窗标签）的份额 | 「后来对象长什么样」——画像轴 |
| **PO-risk / LOGO share** | 维内各族对风险的 Δ | 「和 Y 差绑在一起」——概念相关，**非因果** |
| **注入族 Hit** | 注入时只污染族 g*，看 g* 是否 Top-1/2 | 硬评 L2 |
| **与错误动作隔离** | 文风族高 → 不得触发偏好合并/客服回滚 | 纪律指标（必须过） |

### 2.5 L3 动作与经营怎么评

| 指标 | 定义 |
|------|------|
| **子集动作率** | 工单落在 S* owner 的比例（目标高） |
| **越权动作率** | 安静维被开大动作的比例（目标低） |
| **刷新预算节省** | 1 −（实际刷新维数 / 全维数） |
| **（可选）窗内 KPI 回撤** | 动作后坏 KPI 是否回落——需对照窗，不作唯一因果宣称 |

有客服/转化账时：用 **acted vs ignored** 量 × 单价；**没有**时不要硬编 ¥，用预算节省 + 误动作下降即可。

### 2.6 评估报表长什么样（建议固定模板）

```text
【图谱 use-case 评估 · 窗 Wt】
L0  fire=1  delay=0  quiet_false_fire=—
L1  S*={author:0.41, order:0.33}  Hit@2=1  false_dim={product:0.12}
    告警链: author_cnv — order_empty_path
    vs flat-FSDS 维召回: 持平或更好；误报维更少
L2  author: LOGO register=0.55 → style-only 工单（另账）
    order:  PO empty_path=0.48 → 路径监控；时延 LOGO≈0 → 不讲「决策变慢」
L3  开: 作者素材限流 + 订单空路径 Top-k
    不开: 商户/商品大动作
    子集动作率=1.0  越权=0  刷新维数=2/4
```

## 3. 评估实验怎么设计（可复现协议）

### 3.1 最小硬评协议（推荐先做）

1. **选 4 维** + 每维 若干层特征（或 LLM 四别名）。  
2. **安静基线窗** \(W_{\mathrm{ref}}\)：四维 IID。  
3. **单维 hop**：只改维 \(d^*\)（均值平移 / 方差拉大 / 标签相关污染）。  
4. **双维 hop**（可选）：同时改 \(d_1^*, d_2^*\)，测 Hit@2。  
5. 跑 L1，记 Hit@K / Precision@K / 假维率。  
6. 在真 S* 上跑 L2，记注入族 Hit。  
7. 对照：**无图、全特征 FSDS 再映射回维**——表格并排。

### 3.2 与现有 prototype 对齐

| 步骤 | 仓库落点 |
|------|----------|
| 四维并成特征维 | `feature_dim_attr.py --alias graph` |
| **TencentGR 实数：图定位→FSDS + 注入 Hit@K** | `scripts/tencent_gr/graph_loc_fsds.py` → `results/tencent_gr_fs150/graph_loc_fsds/` · `TENCENT_GRAPH_LOC_FSDS.md` |
| LLM 同构四维 | `--alias llm`（rag/style/text/path） |
| 风格挂作者维 | `FEATURE_DIM_UNIFIED_ATTR.md` |
| 值班输出样例 | 本文 §2.6；原样例见商户图文档 §5 |

当前 `feature_dim_attr` 已具备 **L1 mass/LOGO + L2 within-dim** 的同构评估骨架；硬评 Hit@K 需在注入协议上加一列真值维（下一轮可把 `injected_dim` 写进 summary）。

### 3.3 失败模式清单（评估时对号入座）

| 失败 | 通常原因 | 改刻画还是改评估？ |
|------|----------|-------------------|
| 真坏维进不了 Top-2 | 层 KPI 太弱 / 边噪 / 窗太短 | 先改刻画（层表征） |
| 四维轮流误报 | 未做 L0 / 阈值过松 | 加检测门控 |
| L2 族对、但工单开错 owner | L3 路由表坏了 | 改动作映射，不改 FSDS |
| 文风维触发客服回滚 | 账本纪律破了 | **评估一票否决** |
| 边很多、故事很满、Hit@K 低 | 把 ASSOC 当因果在讲 | 砍叙事，回到维级 Hit |

## 4. 对外怎么讲（justify 话术）

**能说**

- 图谱把「多对象乱局」收成 **维级决策**：先 2–3 维，再维内特征。  
- 评估主考题是 **L1 Hit@K（真坏维）** 和 **L3 子集动作率**，不是边的「可解释故事」。  
- 与多塔/文风并维同一套：风格是作者维上的子问题，不是第二套产品。

**不能说**

- 「图边证明了因果」。  
- 「一次给出全库唯一根因 SKU」。  
- 「图 AUC 高所以贡献 ¥ 高」（中间缺动作与对照窗）。

---

## 5. 一句收束

**刻画**：四（+）维节点 + ASSOC 边 + 滚动窗 + L0/L1/L2/L3 各答一问。  
**评估**：L1 用注入维 Hit@K 做主考；L2 用注入族 Hit；L3 用子集动作率 / 越权率 / 刷新预算；文风另账一票否决。  
**价值**：不是更复杂的图，而是 **更短的决策路径**——先维后特征，只砸子集。
