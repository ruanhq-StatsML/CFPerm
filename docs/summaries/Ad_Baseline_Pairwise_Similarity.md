## 1. 曝光强度 = 买量基线（业务深讲）

### 1.1 它在说什么

投放系统里，转化往往和「这边上堆了多少曝光」同向：预算加了、竞价赢了、定向放宽了 → 曝光↑ → 转化次数也↑。  
ops 面板里 `e_log1p_exp` / `i_log1p_n_exp` 稳居 top，且 **相邻窗 transfer AUC≈0.99**，业务翻译只有一句：

> **「有量的关系更好转化」这件事，下一批评次仍然成立。**

这叫 **买量基线（buy-volume baseline）**，不是「我们发现了作弊因子」。

### 1.2 为什么 AUC≈0.99 ≠ 作弊

| 误读 | 正解 |
|---|---|
| 分数高 = 异常 | 分数高 = **关联很稳**；买量世界里这本就该稳 |
| 强度进 top = 刷量 | 强度进 top = 预算/竞价/定向的 **正常产物** |
| 大促放量 AUC 更高 = 出事了 | 放量时基线更响，往往更「正常」 |

作弊要另找证据：转化极性（突然好得离谱）+ **去量后**末跳/共点 tip + 人审路径，不能单靠 ops AUC。

### 1.3 为什么 ≠ 拿去限投

限投/限频是 **L2+ 动作**，改变的是流量供给，会反过来改曝光强度分布。  
若用「强度能预测转化」去限投，等于：

1. 用买量内生变量当风控分数  
2. 限完量 → 强度分布变 → 分数失真（自我干扰）  
3. 误伤正常放量账户  

所以工单固定句：

> **买量基线可报、可解释「量的故事」；禁止单独作为限投/停投下发依据。**

本看板 `ship_gate` / `allows_ship_model=false` 就是把这句话写死。

### 1.4 还有哪些「基线型」故事（同类、勿限投）

| 基线 | 典型 top | 业务 |
|---|---|---|
| 买量/曝光强度 | `e_log1p_exp`, `i_log1p_n_exp` | 预算放量 |
| 物品热度 | `i_item_pop_rank`, `i_n_users` | 自然爆款/追投 |
| 用户活跃 | `u_n_events`（若未从 content 去掉） | 大号更易转化 |

它们都可以「稳传」，都 **不是** 自动限投开关；限投只跟 极性+content 候选+人审 走。

## 2. Pack-pairwise vs 日历宽窗

| | **Pack / 样本数 pairwise** | **日历宽窗 pairwise** |
|---|---|---|
| 切什么 | 每窗固定 **N 行**（边/prompt/小时行） | 每窗固定 **分钟宽度** |
| 业务适合 | 投放突发、边流不均（**广告默认**） | 内容/社媒按钟点值班 |
| 副作用 | 同 N 日历跨度可差 5× | 同宽度边数可差很多、空箱 |
| 指标表 | `sample_chunk_adjacent_board` cross_pack | DiffDB `adjacent_board` width_min |
| 禁令 | **不要**和宽窗 AUC 横比绝对值 | 同左 |

广告值班：先看边 N=1000/2000 pairwise；日历宽窗只作「若按钟点会怎样」的对照，不替代。

Equal-count 的日历副作用本身就是指标：`mean_span_hours` 越大 → 这批边在时间上越稀。

## 3. Pairwise 逻辑 · 相似度怎么刻画 · 怎么评估

### 3.1 逻辑（再钉一次）

```text
sort(e_last_ts)
for (t0,t1) in pairwise(chunk_ids):   # 或 stride 重叠版
    train = rows[t0]; test = rows[t1]
    选特征(train) → 探针打分(test) → AUC
```

问的是：**这批的关联，下一批还像不像** —— 不是「两窗分布 KL 多少」。

### 3.2 相似度 / 稳定性指标（看板已有 + 建议读法）

| 指标 | 刻画什么 | 高/低业务读 |
|---|---|---|
| **HGB AUC** | 非线性探针下，关联是否 transfer | 高=故事还在；ops 高≠限投 |
| **LogReg AUC** | 线性版同一问题 | 与 HGB 同向→不是树模型幻觉 |
| **\|HGB−LogReg\|** | 探针分歧 | ≥0.15 → 别把非线性优势写成业务必然 |
| **top-5 Jaccard（跨相邻对）** | **驱动名单**像不像 | 高=同一套因子；低=还能预测但换人了 |
| **FSDS∩cmean Jaccard** | 排名选中 vs 均值漂移 | ≈0 → 别用 cmean 冒充预测力 |
| **ops−content AUC gap** | 「量的故事」vs「路径故事」差多远 | 大→先报买量基线，再报末跳 |
| **Δȳ** | 转化水平动不动 | 定 S1/S2/S3，与 AUC 正交 |

**评估口诀（投放）**：

1. 先看 Δȳ（业务结果）  
2. 再看 ops AUC（是不是量基线）  
3. 再看 content AUC + top（去量后还有没有路径嫌疑）  
4. 用 Jaccard 判断「是不是同一套嫌疑」还是「换了一批因子」  
5. 永远不把单指标升格为限投开关

## 4. Intensity × Credit 交叉

边缘三分位只是主效应。交叉四格才回答：

> 「大曝光且高末跳」和「小曝光但高末跳」是不是同一类案？

| | credit_high | credit_low |
|---|---|---|
| **intensity_high** | 大买量 + 末跳重 → 最像「花钱堆到末跳」；S1 时优先辨爆款 vs 刷末跳 | 大买量但归因弱 → 量在空转；偏投放效率/落地问题 |
| **intensity_low** | 少曝光仍高归因 → **路径结构故事更纯**（content 更有价值） | 两弱；常转化稀、pairwise 空 —— 少浪费人审 |

业务动作：

- 交叉格只出 **L1 分流标签**，不出自动停投  
- `I_high∧C_high` + `sign_Dy=pos` → 末跳/刷量队人工辨  
- `I_low∧C_high` → content 话术权重↑（少被量基线淹没）  
- `C_low` 且 y≈0 → 可降抽检，别硬刷 AUC  

实现：`run_subset_pairwise_analysis.py --cross`（见产物四格表）。

## 5. Stride 重叠 pairwise

默认 **不重叠**：窗 `[0,N), [N,2N), …`，`pairwise` 相邻。

| 模式 | 切法 | 何时用 |
|---|---|---|
| 默认 | stride=N | 批次边界清晰、算得快 |
| 重叠 | stride=N/2，窗仍长 N | 怕边界刚好切在放量尖峰上；看结论是否稳健 |

重叠不改变「买量基线≠限投」；只减少「切窗运气」。  
若默认与 stride=N/2 的 ops top / S 族一致 → 结论稳；若大变 → 报「对切窗敏感」，先别升动作。

## 6. 按广告主（merchant）切

审出最终挂的是 **账户/广告主**，不是单条边。

| 做法 | 含义 |
|---|---|
| 边 → `item_feat.122` → `merchant_id` | 账户粒度 |
| 取边数最多的 Top-K 广告主 | 大户值班包 |
| 每户内自行 sort+pairwise | 「这户自己的买量基线 / 末跳」 |

业务：

- 大户 ops 基线高 + 全网一样 → 别单独处罚大户「有量」  
- 某户 **content 异常而同行业 ops 正常** → 才值得进该户审出队列  
- 小户样本不够 N×2 → 合并「长尾户」或拉长窗，禁止对小户报假 AUC

## 8. 投放/审出一分钟复述

1. AUC≈0.99 的曝光强度 = **预算放量的正常故事**，不是作弊证据，**不能限投**。  
2. 限投/升动作只看：转化极性 + 去量 content + 人审。  
3. Pairwise 相似度用 AUC + Jaccard + gap 三件套评估「故事稳不稳、换没换人」。  
4. 交叉看「量×末跳」；重叠看切窗运气；广告主切看账户挂载。  
5. 日历宽窗是另一套尺子，广告默认用边样本 pairwise。
