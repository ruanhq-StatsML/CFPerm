# X / Y / 特征→业务：**Justify 版**

> 只把三件事辩清楚：**(1) Y 为什么是这个 (2) X 为什么是这个 (3) 选出的特征凭什么直接 map 到业务**。  
> 其它（巡检节奏、旁路解冻清单）次要。

---

## 0. 主张（先亮结论）

1. **必须拆两套 (X,Y)**：算法层回答「图上发生了什么」；商业层回答「卡有没有给人省时间」。混用 = 用 tip AUC 冒充人分钟，不可辩护。  
2. **算法 Y 必须是成功结局方向**（`sign_Dy`），不是 tip 本身——否则「路径份额变了」会被误读成「刷量」。  
3. **特征→业务只允许「分流话术 / L1 队列」**，不允许「特征→定罪/L2」——词典 justify 的是 *查法*，不是 *判决*。  
4. **商业门禁必须卡在真人 `useful|not_useful`**：没有商业 Y 的样本，一切灰度/ROI 预测无定义。

---

## 1. Justify：**Y 是什么**

### 1.1 算法 Y —— 为什么是 \(\Delta\bar y\) / `sign_Dy`

| 备选 Y | 为何不取 | 取 \(\Delta\bar y\) 的理由 |
|---|---|---|
| tip 漂移幅度 | tip 只说 X 漂了，不说「假成功」 | 刷量/灌入的业务对立轴是 **成功变多 vs 变少** |
| PO / MMD 分数 | 定位/风险窗分数，运营读不懂当案由 | 案由要一句话能进队列名 |
| 规则命中 | 另一条系统；本包不解冻规则 | 避免双源定罪 |
| 商户黑名单 | 无图因果；易误伤 | 本包 L1 分流，不开名单 |

**定义（可计算）：**  
对定位块 \(K^\star\)，比较两窗成功均值 \(\bar y_{\mathrm{cur}}-\bar y_{\mathrm{ref}}\) → 符号压成 `sign_Dy`∈{pos, neg, flat}。

**Justify 句：**  
业务上「刷量 vs 灌入」的第一刀是极性；没有极性，一切 tip 只能讲「结构变了」（漂移），**不能**讲刷量——这不是口味，是案由可分性。

**现状缺口：** 样例常缺 `direction` → 算法 Y 未落地 → 只能按 flat **保守**讲；这反而 justify「缺 Y 时禁止升 L2」。

### 1.2 商业 Y —— 为什么是人分钟 / 为何门禁用 `useful`

| 层 | Y | Justify |
|---|---|---|
| **主 KPI** | 件均审核人分钟 ↓ | Scope 唯一商业目标；卡的价值 = 少翻页，不是多抓人 |
| **门禁代理** | `useful` / `not_useful`（真人） | 人分钟难即时采集；「有没有帮我少翻页」是同一目标的 **可操作标签** |
| **不取** | smoke useful、Cover、CI 绿 | 接通≠有用；Cover 是注入暴露，不是人用 |

**Justify 句：**  
商业置信门禁卡的是 **商业 Y 的样本量**（`n_human`），不是工程置信。无真人票就报 UR/ROI = 用 X 的管道成功率冒充 Y——不可辩护。

\[
\mathrm{UR}
=\frac{\#\mathrm{useful}}{\#\mathrm{useful}+\#\mathrm{not\_useful}}
\quad\text{仅真人；smoke 剔除}
\]

没有 UR → \(\widehat{\mathrm{harm}}\propto r(1-\mathrm{UR})\) **无定义** → 禁止用预测去调灰度。

## 2. Justify：**X 是什么**

### 2.1 算法 X —— 为什么是 \(K^\star\) 上的 tip 特征

| 备选 X | 为何不取 | 取 \(K^\star\) tip 的理由 |
|---|---|---|
| 全图全特征 | 噪声大、审不完 | Drill 已把「哪块在漂」收到 \(K^\star\) |
| 仅 user_id 名单 | 无结构解释 | 审核要「看哪类结构」，不是裸 ID |
| 仅规则特征 | 与图谱变动脱节 | 本包卖的是图移位上下文 |
| 原始 PO 向量 | 不可读 | FSDS tip = 可读、可进词典的 X 切片 |

**定义：**  
X = 在 \(K^\star\) 上选出的漂移 tip（如 `i_share_linear`, `i_share_last`, `u_span_sec`, `i_n_covisit_*`…）+ 符号。

**Justify 句：**  
X 的正当性来自「**已局部化**」：先 Drill 再 tip，审核负担从全图变成一张卡；本包 **不改 Drill 门**，只消费其输出——X 管线与算法门解耦，回滚只动卡/灰度。

### 2.2 商业 X —— 为什么是「整张卡」不是单个 tip

审核决策吃的是一次呈现：`sign_Dy` + 队列桶 + tip 话术 + SLA。  
单 tip 当 X_biz → 丢极性 → 误 map（linear tip 变「刷量」）。  
**Justify：** 商业层 X = 卡对象；打标的是卡，不是某一个 float。

## 3. Justify：**特征 → 业务 map**（何时「能直接」）

### 3.1 映射规则（唯一合法箭头）

```text
sign_Dy (算法 Y)  ──决定案由族──►  S1刷量 / S2灌入 / S3漂移
tip 特征 (算法 X) ──决定队内话术──►  末跳 / 路径结构 / 短会话 / 共点抽检 …
输出动作                  ──只到──►  L1 队列名 + 读法（人可改队）
```

**能直接 map 的判据（三条全满足才勾「能」）：**

1. **有业务对立解释**（成功升/降/平，或明确修饰如 SLA/共点抽检）  
2. **动作停在 L1 分流**（盯梢/读法/抽检密度），不自动惩罚  
3. **与极性一致**（如短会话配 neg 才像灌入；单 tip 不单独定罪）

### 3.2 表：特征 → 业务（带「凭什么」）

| X / 字段 | 业务 map | 直接？ | **Justify（凭什么）** |
|---|---|---|---|
| `sign_Dy=pos` | 刷量族队列 | **能** | 成功变多是刷量/爆款的公共前提；L1 只分流去核对末跳/爆款，不封号 |
| `sign_Dy=neg` | 灌入族队列 | **能** | 成功变少 ↔ 差流/打压残留的查法；对立于刷量，避免同一 tip 两头打 |
| `sign_Dy=flat`/缺 | 漂移族；慎升 | **能** | X 漂 Y 不动 → 供给/活动优先；**缺 Y 时升 L2 不可辩护** |
| `i_share_last`/`i_credit_last` + | 末跳盯梢 | **能** | 路径末跳份额升 = 可操作查法；须配 pos 才强化「假成功」叙事 |
| `i_share_linear`/`i_credit_linear` | 路径结构漂移队 | **能** | 线性份额是结构描述；**单独不证明刷量**（当前样例主 tip） |
| `u_span_sec` − | 短会话话术 | **能*** | 短跨度 = 劣质会话线索；*无 neg 时只形容结构，不叫灌入 |
| `i_n_covisit_*` | 抽检↑ | **半** | 共现≠团伙；justify 停在抽检密度，禁止对外「认定」 |
| `gap_days` 大 | 同队先清 | **能** | SLA/时效，与案由正交，直接调度 |
| 裸 tip 名 / PO 分 / MMD | 案由/限频 | **不能** | 无极性、无 L1 边界 → 误伤不可辩护 |

### 3.3 反例（证明边界不是抬杠）

| 错误 map | 为何不可辩护 |
|---|---|
| `i_share_linear`↑ ⇒ 刷量 ⇒ 限频 | 缺 `sign_Dy=pos`；结构≠假成功 |
| `covisit`↑ ⇒ 团伙封禁 | 共点只支持抽检；无资金/规则证据链 |
| Cover=1 ⇒ 审出加速成功 | Cover 是注入 X 暴露，不是商业 Y |
| smoke useful ⇒ 解冻 ETA | smoke≠真人商业 Y |

## 4. Justify：**商业门禁卡在打标**

| 问题 | 辩护 |
|---|---|
| 为什么不 CI 绿就放开？ | CI 证的是管道（商业 X 能生成），不证商业 Y |
| 为什么要真人二元标？ | 人分钟难即时采；useful 是同目标的便宜代理，且可按队切片 |
| 为什么 n=1 不够调灰度？ | 单票方差极大；调 r 改变暴露面，需要 UR 稳定估计（建议 n≥5） |
| 等人时为何禁堆 feature？ | 无 Y 基线时新 tip/UI 无法证伪「是否更有用」→ 研发空转 |

**预测（等人中）唯一站得住的：**  
降低 \(T_{\mathrm{ask}\to\mathrm{label}}\)（发 handoff）→ 提高 \(P(\mathrm{READY})\)；其它动作对人分钟的预测符号不确定，故 freeze。

## 5. 现在效果（只对 X/Y/map 说话）

| 主张 | 现状 | 是否已 justify 落地 |
|---|---|---|
| 算法 X→卡 | 出卡/词典/灰度有 | **是**（工程） |
| 算法 Y=`sign_Dy` | 样例常缺 | **半**：规则有、落盘弱；缺则强制当 flat |
| 特征→L1 业务 map | 词典+队列话术有 | **是**（查法级）；**否**（若有人拿去定罪） |
| 商业 Y / 门禁 | n_human=0 | **门禁在生效**；ROI **尚未**被数据证明 |

## 6. 一屏记住

```text
算法:  Y=成功方向(sign_Dy)   X=K* tip
商业:  Y=人分钟↓ (代理=真人useful)   X=整张卡

合法箭头:  Y极性 → 案由族 ;  tip → 队内话术 ;  输出 → 仅 L1
非法箭头:  tip/分数 → 刷量定罪/L2 ;  Cover/CI → 商业成功

门禁:  没有商业Y样本 ⇒ UR无定义 ⇒ 不调r、不解冻、不报人分钟↓
```
