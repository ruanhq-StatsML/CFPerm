# 20-Agent 商业落地 Procedure（反欺诈线索机）

> **不做** math-Eval / 理论 AUC sweep / 公式证明。  
> **要做** 能直接进业务的交付：降审出量、降误伤、缩短案件 SLA、接规则/名单。  
> 激励原则：**平均发力**——20 个 agent 按车道均分，每车 1 个主交付，禁止扎堆刷同一指标。

底座已有：监测波次 → Drill \(K^\star\) → tip+direction 线索卡  
（[`Wave_Drill_Clue_Pipeline.md`](Wave_Drill_Clue_Pipeline.md)）。

---

## 0. 商业目标（一句）

把「图谱变动波次线索」变成 **可派单、可回滚、可计 ROI** 的反欺诈产能，而不是再发一篇评估报告。

ROI 只认业务账（任选可量化的 2–3 个，不必全上）：

| KPI | 含义 |
|---|---|
| 人审件均耗时 ↓ | 线索卡分流是否省时间 |
| 误冻结 / 客诉 ↓ | L2 动作是否可控 |
| 案件发现 Lead（天）↑ | 是否比纯规则更早碰到 |
| 规则∩\(K^\star\) 命中产案率 ↑ | 关联是否值钱 |
| 无效报警占比 ↓ | 波次质量是否够用 |

**禁止**把「W2 AUC / hit@k 涨 0.02」当结项条件。

## 2. 下一步「评估与关联」——商业版（不是 math）

### 2.1 评估 = 人审有用性，不是定理
- **有用率**：人审对线索卡点「有用/没用」（车道 12+18）  
- **省时**：同复杂度案件，有卡 vs 无卡的处理分钟差  
- **误伤**：L2 灰度池客诉 / 解封率  

样本够 2 周即可定去留；不要求显著性检验。

### 2.2 关联 = 接现有钱货系统
优先关联顺序（直接变现）：

1. **规则引擎**（车道 5）：命中规则的实体若 ∈ \(K^\star\) → 插队  
2. **名单/图数据库**（车道 2）：\(K^\star\) 日更进现网黑/灰名单管道  
3. **工单/SOAR**（车道 1+8）：波次自动开单，卡贴在单里  
4. **策略中台**（车道 6+7）：L1/L2 开关化，可回滚  

「关联」成功标准：现网某一条流水线上 **多了一个真实输入**，而不是又一份 markdown。

## 3. 两周节奏（平均发力后就停手加码）

**Week 1 — 接通**  
车道 1,2,4,5,14,20 先亮：工单、名单、看板、规则交、API、开关。

**Week 2 — 灰度**  
车道 6,7,12,13,18：加监、限频试点、有用率、对照周、回流。

**结束条件（满足即收）：**  
- ≥1 条现网关联通路通了  
- 人审有用率有数（哪怕 N 小）  
- L2 有回滚开关  
- 20 车每车都有可点产出（允许 2 车延期，不允许 10 车挤在模型调参）

**不做：** 扩 20 个 math ablation；为抬 AUC 改 Drill 门；无业务 KPI 的「模型 SOTA」PR。

## 5. Takeaway

下一步不是更深的 Eval，而是 **20 车均分把波次/Drill/线索接到工单·名单·规则·灰度**。  
评估看人审有用与误伤；关联看现网是否吃上 \(K^\star\)+direction。  
激励平均发力后，**够用就收**——商业价值来自接通，不来自数学。
