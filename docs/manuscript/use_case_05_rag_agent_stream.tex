\subsection{Graph-RAG, hybrid retrieval, and agent next-step}
\label{sec:usecase-rag-agent}
Any stream whose data-generating map moves in continuous time can be written as one prediction table
\((X,Y,\mathrm{batch})\).
The estimand is whether the frozen serving policy \(P(Y\mid X)\) is still the same object.
Hallucination rate, refusal rate, and single-channel Recall@\(k\) are not \(Y\).
The two continuous-time jobs and ordinary serving maps are \texttt{docs/manuscript/online\_serving\_gates.tex}.

\paragraph{Shared loop.}
Fit a probe on a reference window of the deployed pack (prompt + retriever/graph/tools + generator).
For each arrival batch, score excess error against that baseline, form a rank \(p\)-value, and apply online FDR
(ADDIS/SAFFRON; asynchronous if retrieval windows overlap).
Last-two \texttt{hop\_fires} is the adjacent-window gate.
On fire: stop treating the current context or tool trace as gold; refresh cheapest-first; reset the error pool,
burn-in, and testing wealth before the next cycle.

\paragraph{Graph-RAG.}
\(Y\) is whether the citation lands on an edge, or the supporting nodes sit in the served pack.
One serving batch is the aggregate of subgraph features on that window
(node/edge counts, mean degree, connected components, query seeds, largest-component fraction).
Optional \(T\in\{0,1\}\) separates local subgraph from global community queues.
A hop is a graph-pack or community recompute (drop or rewire edges, then the same aggregate)---not single-node relevance.
Refresh order: prompt, then retrieval routing, then re-extract/re-summarize the graph; generator last.
Promote a shadow pack only if the next-window error recovers and last-two is quiet.

Hotpot on disk is a Graph-RAG \emph{snapshot}, not a time stream
(\texttt{xy\_hotpot\_pairs.csv}: 10 titles as nodes, \(Y=\) supporting title).
The \texttt{batch} column is query index, not arrival time.
Window-level aggregate tables: \texttt{scripts/prototype\_graph\_pack\_batch\_agg.py}.

\paragraph{Hybrid retrieval.}
One request rewrites, retrieves sparse and dense in parallel, fuses (e.g.\ RRF), reranks, and generates.
\(Y\) is validity of the answer given the \emph{fused} context, not BM25-only or dense-only recall.
\(X\) includes channel overlap, rerank margin, \(k_s,k_d\), and embedding/reranker/prompt ids.
A hop is an index, chunker, embedding-model, or fusion-weight change that breaks the frozen pack.
Next-step evaluation is a live/shadow promotion test on the same queries, not a Recall@\(k\) leaderboard.

\paragraph{Agent next step.}
Each hop is observe \(\to\) choose tool \(\to\) call.
\(Y_{\mathrm{hop}}\) is hop legality (schema, admitted tool, no loop) and is available at hop end.
Episode success \(Y_{\mathrm{task}}\) is a slower, separate stream.
\(X\) is the observation embedding, last tool id, argument shape, hop index, and tool-schema version.
A hop is a schema/prompt fracture or a loop; on fire, do not auto-commit and do not write the trace into gold.
If the agent first retrieves a graph or hybrid index, retrieval fire and tool fire are stacked gates, not one score.
