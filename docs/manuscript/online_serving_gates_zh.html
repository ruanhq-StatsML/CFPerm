两件连续时间的事

检测的是 P(Y | X) 还是不是同一张 serving 地图。
我们做的是连续时间审核，和 agent 推理。其余按普通 serving，同一套闸。

产品 use-case

LLM 推理逻辑：连续到达的一跳

  1. 观察当前 serving 包（政策 / 工具 schema / 图包 / 融合索引）。
  2. 模型走下一步：写回复 / 选工具 / 从子图引用 / 融合两路给答案。
  3. 写下这一跳的 Y。X 是 serving 几何，不是原文。
  4. 冻住的 fref 只预测 P(Y | X)。
  5. T = MSE − Eref → 秩 p → 在线 FDR。
    quiet 当金标； fire 当前包不当金标，换最便宜的包，reset。

四个产品共用这一条 hop。审核可以是多步：每一跳一行，Y 仍是过/不过。没有别的对象。

对象

冻住的地图还在不在

不是归因，不是生成模型，也不是把旁路指标写成 Y。

表：(X, Y, batch)，可选队列 T ∈ {0,1}

凡是连续时间在变、能写成这张表的流，都可以走这一套。

Last-two hop_fires

在 Bt−1 上重 fit，打 Bt。
Fire = 相邻两窗的地图 hop 了。
第一跳永远 quiet。

主任务

连续时间审核，和 agent 推理

连续时间审核

Y = 过 / 不过。
Fire = 政策包或 judge 换代。
不是拒绝率，不是 HH chosen。

Agent 推理

Y = 这一跳 / 路径是否合法。
Fire = 推理断了，或开始空转。
不是幻觉率，不是任务最终成功。

Graph-RAG、混合检索：同一套闸，只换 Y，按普通 serving 写。

普通 serving

图包：batch = 图特征聚合

每条请求一张子图：节点、边、平均度、连通片、query seed、seed 比例、最大片。

一个到达窗把这些特征 aggregate 起来，就是这一窗的 X。
Y = 支撑节点落在 seed ∪ 一跳邻居。

Community 换代：切点后 drop / rewire 边，再做同样的聚合。不要另造奇怪的 X。

Hotpot 盘上是题库快照，没有墙上时间。Prototype 用文件顺序只演示表形。

Serving 循环

Quiet 留金标，Fire 换包

burn-in → 每窗打 Δt → 在线 FDR

Quiet：金标保留，误差入池。

Fire：当前包不当金标；从最便宜的刷新做起；整池 reset。

晋升：影子窗误差回来 且 last-two quiet。
