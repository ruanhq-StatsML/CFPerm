\begin{abstract}
We treat OnlineRFPerm as a \emph{serving monitor}, not as a new language-model
method. Four public QA corpora---HaluEval, SQuAD, HotpotQA, and TruthfulQA---are
cast into one tidy stream
\texttt{t\_idx / batch / question / answer / y}.
A shallow probe is frozen on a reference window with
$n_{\mathrm{ref}}=100$, and OnlineRFPerm is run as an online regime clock on
the trail. Quiet batches keep knowledge in the prompt; hop batches drop context
and force invent-style decoding, inducing a quality-law change.
We report fire index, detection delay, quiet/hop label rates, and a full
\texttt{first}$_k$ comparison against the \texttt{onlinePermOOB} detector bank
(BOCPD, Page--Hinkley, ADWIN, DDM, STEPD, HDDMA, ECDDWT) under the manuscript
trail-batch consecutive-fire rule.
On three of four datasets OnlineRFPerm fires at the hop (delay~$0$).
HotpotQA is a negative control under the current overlap label: quiet $y$ is
already saturated, so there is no regime contrast to detect.
\end{abstract}

\section{Scope}
\paragraph{What this delivers.}
A production-shaped wiring:
live or simulated LLM answers $\to$ tidy dataframe $\to$ OnlineRFPerm fire
$\to$ action route (\texttt{model\_rollback} / \texttt{retrieval\_refresh} /
\texttt{audit\_topk}).
The product claim is a \emph{timestamped quality-regime hop}, which is the
prerequisite for opening a contrast window and choosing an arm.

\paragraph{What this is not.}
Not a fact checker, not a causal root-cause engine, and not an LLM training
paper. A fire opens a window and a gate; it does not assert that any single
answer is factually wrong.

\paragraph{What else is deliberately out of scope here.}
(i)~acted-vs-ignored ¥ ledgers (optional later, if a cost ledger returns);
(ii)~agent path-subset localization (FSDS/LOGO on tool traces);
(iii)~replacing RAG evaluation suites or human fact-check queues;
(iv)~unsupervised ``semantic quality'' scores without a $Y$ source.
Those are adjacent product layers; they are not required to make the monitor
claim.

\paragraph{Shared regime.}
\begin{itemize}[leftmargin=1.2em]
\item \textbf{Quiet} (batch $<$ cut): faithful system prompt; knowledge included.
\item \textbf{Hop} (batch $\ge$ cut): invent system prompt; knowledge removed.
\item Label $y=1$ (bad) from low token-overlap faithfulness against knowledge,
with light invent-style heuristics on the hop window.
\end{itemize}

\section{Protocol}
\paragraph{Clock.}
$n_{\mathrm{per}}=20$, $\mathrm{cut}=5$ $\Rightarrow$
$n_{\mathrm{ref}}=n_{\mathrm{per}}\times\mathrm{cut}=100$.
Total $n_{\mathrm{batches}}=10$: trail length $=100$ observations / $5$ batches.

\paragraph{OnlineRFPerm (batch).}
On consecutive batches $B_{t-1},B_t$:
\begin{align*}
\mu_0 &\leftarrow \mathrm{fit\_online\_probe}(X_{t-1},Y_{t-1}),\\
e_t &= \mathrm{err}(\mu_0; X_t,Y_t),\\
\mathrm{fire}_t &\iff e_{t-1}\ge e_{\mathrm{floor}}
  \;\wedge\; e_t/e_{t-1}\ge \gamma.
\end{align*}
Reported: first fire batch, detection delay $=\mathrm{fire}-\mathrm{cut}$,
and quiet/hop mean $y$.

\paragraph{Manuscript \texttt{first}$_k$.}
Let \texttt{det} be the boolean trail (batches \emph{after} cut only). Then
\begin{verbatim}
def first_k_consecutive(det, k):
    det = np.asarray(det, dtype=bool)
    for i in range(len(det) - k + 1):
        if det[i:i+k].all():
            return i   # trail batch index; 0 = first batch after cut
    return None
\end{verbatim}
Index $0$ is the first trail batch; --- means never.
\texttt{first}$_1$ is the headline onset; \texttt{first}$_2$/$_3$ are
sustained-onset checks (consecutive trail fires).

\paragraph{Baseline bank.}
Following \texttt{onlinePermOOB\_algo.py}: freeze a probe on the reference
window, build a scalar OOB/error stream on the trail, then run BOCPD,
Page--Hinkley, ADWIN, and frouros (DDM, STEPD, HDDMA, ECDDWT). All methods are
scored with the same trail-batch \texttt{first}$_k$ rule.

\paragraph{Read.}

$y$ near one, and OnlineRFPerm fires at cut (delay~$0$).

(long multi-paragraph contexts make token-overlap labels too harsh), not as a
method failure.

\paragraph{How to read the grid.}
\begin{itemize}[leftmargin=1.2em]
\item \textbf{Onset ($k=1$).}
On HaluEval / SQuAD / TruthfulQA, OnlineRFPerm, BOCPD, Page--Hinkley, ADWIN,
and HDDMA all report onset at trail index~$0$---aligned with the injected hop.
\item \textbf{Sustained onset ($k=2,3$).}
OnlineRFPerm typically fires once at the hop then returns quiet on later trail
batches (error ratio collapses after the jump). That is expected for a
ratio-gate clock: headline delay is~$0$, but consecutive multi-batch fires are
rare. DDM / STEPD / ECDDWT stay hot across the trail ($k=2,3=0$), which is a
different operating point---more sensitive, less selective.
\item \textbf{HotpotQA.}
No usable quiet$\to$hop contrast under the current label. OnlineRFPerm and most
baselines do not fire; STEPD fires throughout (vacuous under saturation);
BOCPD reports a late singleton ($k=1=4$). Do not score methods on this column
until faithfulness labeling is tightened.
\end{itemize}

\section{Action routing}
On fire:
\begin{itemize}[leftmargin=1.2em]
\item low \texttt{rag\_hit} $\to$ \texttt{retrieval\_refresh};
\item fire with adequate retrieval support $\to$
\texttt{model\_rollback} / canary + \texttt{audit\_topk} via \texttt{po\_risk0}.
\end{itemize}
Quiet $\to$ standard path; audit weights anneal toward uniform.

\section{Discussion}
\paragraph{Claim that is supported.}
Under a shared serving form and $n_{\mathrm{ref}}=100$, OnlineRFPerm provides a
delay-$0$ hop timestamp on three QA streams with a sharp quiet$\to$hop label
change, and matches the manuscript onset of the stronger selective baselines.

\paragraph{Caveats.}
\begin{enumerate}[leftmargin=1.2em]
\item Numbers in this note use the mock generator scaffold unless otherwise
stated. Swap to transformers/vLLM for production-facing regeneration; keep the
same parquet schema and \texttt{first}$_k$ scoring.
\item HotpotQA is not diagnostic until overlap-based $y$ is replaced or
calibrated for long contexts.
\item Sustained-fire ($k\ge 2$) is not OnlineRFPerm's primary claim; the primary
claim is onset delay. Report both, as in the PointCloud tables.
\item DDM/STEPD/ECDDWT consecutive fires should be read as sensitivity, not as
a free win: a serving monitor that stays permanently on is operationally costly.
\end{enumerate}

\paragraph{What else (adjacent, not required for this claim).}
\begin{enumerate}[leftmargin=1.2em]
\item Production log adapter + $Y$-source dictionary
(\texttt{human\_correction} $>$ judge $>$ escalation $>$ synthetic).
\item Gate / $e_{\mathrm{floor}}$ calibration on quiet false-fire rate.
\item Path-subset localization after fire (agent tool traces).
\item Optional acted-vs-ignored cost ledger once unit economics exist.
\end{enumerate}

\section{Conclusion}
\begin{enumerate}[leftmargin=1.2em]
\item The use-case is intentionally narrow: tidy inference streams + OnlineRFPerm
as a regime clock.
\item With $n_{\mathrm{ref}}=100$, three of four datasets show delay-$0$ fires at
the injected hop; HotpotQA needs label/context handling before it is diagnostic.
\item Baselines must be scored with the same trail-batch \texttt{first}$_k$ rule;
raw delay alone is not enough for manuscript comparison.
\item The next hardening steps are a real generator backend, tighter Hotpot
faithfulness, and quiet-window false-fire calibration---not a new detector
family.
\end{enumerate}
